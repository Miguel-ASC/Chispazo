# Colaborar en Chispazo

1. Describe el problema o la mejora antes de empezar.
2. Crea una rama desde `main`, por ejemplo `docs/instrucciones-locales` o `fix/filtro-categorias`.
3. Mantén cada cambio enfocado. No incluyas credenciales, archivos `.env`, dependencias instaladas ni artefactos compilados nuevos.
4. Usa mensajes de commit concretos: `docs: explica cómo iniciar el backend` o `fix: corrige el filtro por categoría`.
5. Abre un pull request explicando el comportamiento anterior y el nuevo, cómo verificaste el cambio y cualquier limitación. Adjunta una captura cuando modifiques la interfaz.
6. En cambios de datos o API, indica los requisitos de MySQL y las rutas afectadas. No presentes comprobaciones no realizadas como si hubieran pasado.
7. Revisa los comentarios del equipo antes de integrar el cambio.

Para reportar un problema, incluye los pasos para reproducirlo, el resultado esperado, el observado y el entorno. Omite contraseñas, tokens y datos de usuarios.
